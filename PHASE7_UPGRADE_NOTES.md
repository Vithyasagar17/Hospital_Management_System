# Phase 7A — PostgreSQL, Alembic & Database Modernization

Phase 7A moves Medora HMS from runtime/ZIP-era schema patching to a migration-owned database lifecycle suitable for production deployments.

## Added

- PostgreSQL support through `HMS_DATABASE_URL` / `DATABASE_URL`.
- Automatic normalization of hosted `postgres://` and `postgresql://` URLs to the psycopg 3 SQLAlchemy driver.
- `psycopg` production driver dependency.
- Flask-Migrate / Alembic migration history under `migrations/`.
- Immutable Phase 6 schema baseline (`20260910_0001`).
- Production query indexes (`20260910_0002`).
- Runtime schema mutation disabled by default.
- Legacy Phase 1–6 SQLite upgrader retained only behind `HMS_LEGACY_SCHEMA_UPGRADE=1`.
- Portable SQLAlchemy inspection in the legacy upgrader instead of direct `PRAGMA table_info` calls.
- `datetime.utcnow()` replaced by a centralized `utc_now()` compatibility helper, removing Python 3.13 deprecation warnings while preserving existing naive-UTC columns.
- Remaining SQLAlchemy 2.x `Query.get()` calls replaced with `db.session.get()`.
- PostgreSQL partial unique-index support for active waitlist entries.
- Composite indexes for the busiest scheduling, inpatient, lab, billing, reminder, waitlist and audit queries.
- `create_db.py` converted into a local-SQLite-only reset that rebuilds the schema from Alembic before seeding.

## Existing Phase 6 SQLite database — one-time adoption

Back up your current database first:

```powershell
Copy-Item .\instance\hms.db .\instance\hms-phase6-backup.db
```

The current Phase 6 database already contains the schema represented by migration `20260910_0001`, so **do not run the baseline migration against it**. Mark that baseline as already present, then apply the Phase 7A index migration:

```powershell
python -m flask --app run db stamp 20260910_0001
python -m flask --app run db upgrade
python -m flask --app run db current
```

Expected current revision:

```text
20260910_0002 (head)
```

From this point onward, schema changes belong in Alembic migrations instead of `schema_upgrade.py`.

## Fresh local SQLite database

For a completely fresh database, either run migrations directly:

```powershell
python -m flask --app run db upgrade
```

or intentionally recreate and seed the local demo database:

```powershell
python create_db.py
```

`create_db.py` refuses to reset PostgreSQL.

## PostgreSQL setup

Create a PostgreSQL database/user, then point HMS at it:

```powershell
$env:HMS_DATABASE_URL="postgresql://medora_user:strong-password@localhost:5432/medora_hms"
python -m flask --app run db upgrade
python run.py
```

`postgres://...` URLs from hosting platforms are also accepted. Internally they are normalized to `postgresql+psycopg://...`.

To return to the default local SQLite database in the same PowerShell session:

```powershell
Remove-Item Env:HMS_DATABASE_URL -ErrorAction SilentlyContinue
Remove-Item Env:DATABASE_URL -ErrorAction SilentlyContinue
```

## Migration workflow from Phase 7 onward

After changing a model:

```powershell
python -m flask --app run db migrate -m "describe schema change"
```

Review the generated migration carefully, then:

```powershell
python -m flask --app run db upgrade
```

Useful commands:

```powershell
python -m flask --app run db current
python -m flask --app run db history
python -m flask --app run db downgrade -1
```

Never run an autogenerated migration without reviewing constraints, defaults, indexes and data-migration behavior.

## Legacy escape hatch

For an old pre-Phase-7 SQLite copy that has never reached the Phase 6 schema, the old compatibility upgrader can still be invoked temporarily:

```powershell
$env:HMS_LEGACY_SCHEMA_UPGRADE="1"
python run.py
```

After it reaches the Phase 6 schema, unset the flag, stamp `20260910_0001`, and run `db upgrade` as described above. The legacy path is SQLite-only and must not be used for PostgreSQL.

## Timestamp policy

The existing schema uses SQLAlchemy `DateTime` columns without timezone metadata. Phase 7A therefore keeps **system timestamps as naive UTC by convention** while replacing deprecated `datetime.utcnow()` calls with `utc_now()`.

Appointment/availability schedule times remain hospital-local wall-clock values and are not converted to UTC by this helper. A future schema migration can move system timestamp columns to timezone-aware PostgreSQL types without mixing that change into the database-platform migration.
